# AI Rewards Optimization & Spend Analytics

**For:** Uno Wallet — AI Business Analyst, full-time (YC P26 startup)
**Author:** Bhupesh Chandra Dimri
**Stack:** Python 3, pandas, scikit-learn, matplotlib

## One-liner

A card-routing optimiser, churn predictor and rewards-yield forecaster for an
AI wallet that routes each purchase to the card earning maximum points:
the routing rule is optimal by construction (+51.4% points vs users' own
card choice), logistic regression predicts churn at AUC 0.995, and next-month
yield forecasting is honestly reported as the weak module (linear MAPE 74.7%).

## ⚠️ Synthetic data — read first

All users, cards, transactions and points in this project are **synthetic**,
generated by `src/data_gen.py` with a known, auditable process. The five cards
are fictional. **Nothing here is real Uno Wallet data**, a real card product,
or a claim about real Uno Wallet users. Results describe the synthetic world
only — including the 51.4% routing lift, which assumes users mostly use one
default card; a real user who already optimises would see less.

## Results (from the executed pipeline)

| Problem | Best approach | Result |
|---|---|---|
| Card routing | Earn-rate rule (optimal by construction) | +51.4% points; users match optimal card 35.7% of the time |
| Churn (silent in month 12) | Logistic regression | AUC 0.995 (RF 0.992, threshold rule 0.869) |
| Next-month yield | Linear regression | MAPE 74.7%, R² 0.20 (RF 84.4%) |
| Card choice (ML vs rule) | Random forest | 59.3% agreement — the rule stays the router |

## Honest findings

- The **rule beats ML on routing** — and the **simple models beat random forest**
  on churn (logistic 0.995 vs RF 0.992) and on yield (linear 74.7% vs RF 84.4%).
  All three are reported, not hidden.
- Churn AUC 0.995 reflects a pronounced synthetic disengagement ramp; real-world
  churn will be harder. The transferable finding is the ranking of signals
  (recency dominates), not the 0.995.
- Monthly points are noisy (R² 0.20) — the next step is weekly granularity and
  user-segment models, not a bigger model.
